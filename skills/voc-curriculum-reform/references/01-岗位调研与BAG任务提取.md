# 01 岗位调研与 BAG 典型任务提取

> 目标：把"企业要什么人"变成一张可追溯的任务表。这一环节做虚了，后面所有课标都是空中楼阁。

---

## 一、三源输入（不允许单源下结论）

| 源 | 采集方式 | 解决什么 | 典型样本量 |
|---|---|---|---|
| ① 一线专家深度访谈 | 面对面/线上半结构化访谈，1-1.5h/人，录音转写 | 拿到"活是怎么干的"细节与隐性经验 | 5-8 位资深专家，覆盖产业链不同环节 |
| ② 企业访谈调研报告 | 结构化问卷 + 访谈，覆盖不同规模企业 | 拿到面上的分布与共识 | 20-30 位受访者，10-15 家企业 |
| ③ 市场岗位 JD | 招聘平台抓取真实岗位说明书 | 拿到任职资格原文与薪酬带 | 4-6 个核心岗位 |

**交叉印证规则**：同一结论至少两源支持才写入任务表；三源冲突时，以"一线专家 + JD 原文"为准，并在备注列写明冲突点。
**固定表述**：*三源交叉印证 · 消除单源偏差 · 保障数据可追溯*。

### 访谈提纲（四维十二问，可直接用）

**A. 工作内容维度**
1. 您这个岗位一天/一周的典型工作有哪些？请按发生频率排一下。
2. 最近一次让您加班/头疼的活儿是什么？难在哪一步？
3. 哪些活是新人来了就能干、哪些必须带半年？

**B. 能力需求维度**
4. 招新人时，您最看重哪三项能力？为什么？
5. 一个新人最容易在哪一步出错？出错的后果是什么？
6. 您怎么判断一个人"能独立干活了"？有没有具体的标志？

**C. 技术栈维度**
7. 现在现场主流的设备/协议/平台是什么品牌型号？
8. 这两年有什么技术被换掉了？换成了什么？
9. 哪些环节开始用 AI 工具了？用到什么程度？

**D. 职业发展维度**
10. 从入行到独当一面大概几年？中间要过哪几道坎？
11. 这个岗位往上走是什么？横向能转到哪？
12. 如果让您给学校提一条建议，您会说什么？

### 调研报告骨架（六章）

1. 调研背景与方法（对象、样本、工具、时间）
2. 产业与岗位全景（产业链位置、岗位群、需求规模与趋势）
3. 岗位能力需求分析（TOP 能力项排序 + 频次统计）
4. 典型工作任务清单（初稿，带来源标注）
5. 核心发现（5-9 条，每条配一句原话或数据）
6. 对专业建设的建议（课程、实训、师资、证书）

### 高频核心发现（可作观察点，不能直接抄成结论）

| 发现类型 | 含义 | 对课程的要求 |
|---|---|---|
| 实践性认知落差 | 学校讲的"做一条数据链路"与企业说的不是一回事 | 情境必须还原真实约束（成本、停线、交付） |
| 确定性优先 | 工业网络第一原则是确定性，不是带宽 | 教延迟/抖动/丢包，而不是只教通不通 |
| 文档即职业尊严 | 优秀工程师的交付文档规范完整 | 文档纳入评分，"无文档不通过" |
| 从执行者到思考者 | 会看数据流/信号流才能排故 | 训练数据流分析，而不只是操作步骤 |
| 体力密集→脑力密集 | AI 接管重复劳动，人做判断 | AI 工具前置，但判断与复核留给人 |
| 信息不完整下的判断 | 现场信息永远缺，不能等齐了再干 | L3 任务必须设计"缺信息"情境 |

## 二、BAG-GY 七步法（执行版）

### 步骤 1｜组建专家小组
一线工程师 ≥ 60%，覆盖大/中/小企业与不同工龄；教师只做记录与追问，不主导结论。

### 步骤 2｜采集工作过程素材
必备五件套：岗位说明书、作业指导书（SOP）、工单/派工单样本、交付文档样本、一次跟岗观察记录。

### 步骤 3｜归纳工作领域（3-6 个）
判据：一个工作领域 = 一类相对独立的工作对象 + 一组相邻任务 + 一种典型工作场所。
命名句式：**"对象 + 动作"**（工业数据采集与标识解析 / 边缘计算系统运维 / 工业网络规划与运维 / 工业互联网平台运维）。

### 步骤 4｜提炼典型工作任务
- **合格任务的三个必备件**：明确的起点（接到什么）、可描述的过程（怎么干）、可交付的终点（交出什么）。
- **不合格写法**：写职责（"负责设备运维"）、写态度（"认真负责"）、写知识点（"掌握 Modbus 协议"）。
- **粒度**：一个任务通常 0.5-8 学时能完整走一遍；超过 16 学时说明该拆，少于 2 学时说明该并。

### 步骤 5｜描述工作过程与组织形式
工作过程写成**编号步骤列表**（4-6 步），每步写清"动作 + 依据 + 输出"。
工作组织形式只能用现场真实形态，常见六种：

| 形态 | 适用等级 | 特征 |
|---|---|---|
| 按操作手册执行，指导人逐项确认签字 | L1 | 有明确 SOP，双签留痕 |
| 一对一带教，示范+跟随，每步实时记录 | L1 | 师傅在旁，安全类任务 |
| 独立操作 + 自检 | L2 | 有自检清单，一次性成功率可量化 |
| 小组协作，1 人操作 1 人验证 | L2 | 双人确认，适合配置类 |
| 独立运维 + 周期性巡检 | L3 | 有 SLA、有值班 |
| 应急响应 + 24h 值班对接 | L3 | 停线压力，先保产后溯因 |
| 安全审计 + 团队协作 | L3 | 基线与合规，有回退预案 |

### 步骤 6｜标注关联信息（Table1 七列）
核心技能、岗位设置情况（岗位名/部门/场所/设备/跨部门协作）、关联 JD 与任职资格原文、对应程度（🔴 高度 / 🟡 中度 / ⚪ 弱）、转化课程建议、双元制对应技能、备注（AI 融合点 + 调研校准点）。

### 步骤 7｜转化为课程建议
每个任务写清"落哪门课 / 哪个模块 / 多少学时"，并注明是"独立课"还是"LF 模块嵌入"，避免同一内容在两处重复计学时。

## 三、L1-L4 定级判据（避免越级）

| 判据 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|
| 依赖程度 | 依赖手册与他人在场 | 独立，有自检 | 独立，且能处理异常 | 独立，且能指导他人 |
| 信息完整度 | 信息齐全 | 信息基本齐全 | **信息不完整**仍能判断 | 信息冲突时能定标准 |
| 输出物 | 记录表（他人在签字） | 配置文档、检测报告 | 排故报告、优化方案 | 方案设计、标准/规范 |
| 量化门槛示例 | 步骤完成率 100% | 一次性成功率 ≥80% | 可用率 ≥99%、响应 ≤15min | 方案被采纳/带教 ≥1 人 |
| 常见误判 | 写成"独立完成" | 门槛缺失（没写成功率） | 只写"会排故"没写情境 | 把"能优化参数"当 L4 |

**等级分布自查**：L1 约 17%、L2 约 33%、L3 约 42%、L4 约 8%。偏离超过 ±10 个百分点要写说明。

## 四、Table1 列规范

| # | 列名 | 填写要求 |
|:---:|---|---|
| 1 | 序号 | 与能力原子编号前缀一致 |
| 2 | 工作领域 | 步骤 3 的领域名 |
| 3 | 典型工作任务 | "编号 + 动宾短语"，如 1.1 工业通信协议配置与数据点映射 |
| 4 | 等级 | L1/L2/L3/L4 |
| 5 | 工作过程/步骤拆解 | 4-6 步编号列表，每步含动作+依据+输出 |
| 6 | 工作组织形式 | 七种形态之一，写全条件（几人、谁签字、按什么） |
| 7 | 关联核心技能 | 3-6 项，术语用现场说法 |
| 8 | 岗位设置情况 | 岗位名/部门/场所/设备/跨部门协作 五项 |
| 9 | 关联 JD 岗位与任职资格 | 引用 JD 原文编号，标对应程度 |
| 10 | 转化课程建议 | 课程→模块（学时），标独立课/嵌入 |
| 11 | 德国双元制对应技能 | 工种名 + 技能条目 |
| 12 | 对应程度 | 🔴/🟡/⚪ |
| 13 | 备注 | AI 融合点、调研校准点、安全要点 |

## 五、示范行（工业数据采集方向，L2）

| 项 | 内容 |
|---|---|
| 任务 | 1.2 多设备协议配置与数据质量基础检查 |
| 等级 | L2 |
| 工作过程 | ①获取设备清单与通信参数表，确认协议类型，制定配置计划；②用 AI 协议分析工具生成配置模板，按 Modbus TCP/RTU 与 OPC UA 帧结构选参数；③独立配置 ≥2 种协议网关，逐台连通性测试与数据校验，异常逐段隔离；④按规则做异常值标记与缺失值统计，生成质量评估报告；⑤输出配置文档与质量日志，自检一次性成功率 ≥80% |
| 组织形式 | 独立操作 + 自检 |
| 核心技能 | 协议帧结构与参数含义、网关独立配置、连通性测试、基础数据质量指标（完整率/重复率/异常值占比）、AI 工具使用、逐段隔离排查 |
| 岗位设置 | 工业数据采集技术员（初级）；生产制造部/数采实施组；产线现场与配置工位；工业网关、PLC、Modbus Poll、OPC UA 客户端、AI 协议平台；独立对接 MES/物联网平台团队 |
| JD 关联 | 职责③协议配置点位并对接平台；任职资格③常用工业协议、④至少一种编程语言与 SQL 基础；🔴 高度对应 |
| 转化课程 | LF1 模块2（多设备联调 15h）+ 模块3（数据质量基础 10h）；独立课《计算机网络基础》《电工电子技术》已覆盖底层 |
| 双元制 | Technische/-r Systemelektroniker/-in – Protokollkonfiguration |
| 备注 | AI 协议识别与模板生成；从 SOP 依赖（L1）到独立操作（L2）的跃迁；为 L3 数据治理铺垫 |

## 六、常见返工点（来自多轮评审的真实修正）

| 问题 | 症状 | 修正 |
|---|---|---|
| L1 越级 | 六步全写"独立执行" | 改为"按手册执行 + 指导人逐项确认"，每步标 L1 行为特征 |
| 匹配度错位 | 任务写协议配置，课程建议指向"程序设计基础模块2" | 换成对口模块（传感器/电工/网络），并说明为何对口 |
| 学时重复 | 同一模块在独立课与 LF 里各算一次 | 建学时台账，独立课已覆盖的只保留"应用学时" |
| 步骤格式不一 | 有的用六步法、有的用编号列表 | 全表统一为编号步骤列表（4-6 步） |
| 课程漏项 | 有些课程从未出现在任何任务的转化建议里 | 做覆盖率矩阵，空行空列必须解释或补任务 |
| 岗位设置空泛 | 只写"相关企业" | 填五项：岗位名/部门/场所/设备/跨部门协作 |

## 七、交付时的三句话

1. "这 12 项任务来自 X 位受访者、Y 家企业，每一列都能指回原始素材。"
2. "等级分布是 L1 17% / L2 33% / L3 42% / L4 8%，我们把培养重心放在 L2-L3。"
3. "每项任务都标了对应的双元制工种和 JD 条目，对应程度不够的我们没有硬凑，写在中度/弱对应里。"
