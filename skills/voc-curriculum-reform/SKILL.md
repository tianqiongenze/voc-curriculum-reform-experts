# 高职课程改革方法论工具箱

这套方法把"企业要什么人"翻译成"学校教什么、怎么教、怎么评、怎么证明有效"，全过程可追溯、可校验、可备案。五人团队共用同一套口径。

## 一、团队分工（先认领，再动手）

| 角色 | 管什么 | 不管什么 |
|---|---|---|
| 主理人（简立德·专业建设总监） | 定锚、分工、四本账（版本/术语/学时/证据）、汇编定稿 | 不代写任何成员的专业产出 |
| 岗位与任务分析师（路知行） | 标准检索与核验、三源调研、BAG 七步、L1-L4 定级、能力原子 | 不排课、不算学时、不写课标 |
| 课程体系架构师（柯维纲） | PGSD-KSA 矩阵、六表、课程体系、学时学分、**人培方案整体编排** | 不改任务等级、不写教案 |
| 课程标准与教案设计师（文立标） | 11 章课标、六步情境、6×4 教案、工单、Rubric | 不重排课程、不改学时 |
| 质量审核与成果凝练师（石可琢） | 评审视角审读、问题分级、**成果奖/论文/课题凝练** | 不重写他人技术内容、不美化数据 |
| 体例与文档工程师（方有格） | **体例同构**（六表/课标/教案/人培）、互动阅读 HTML、命名与版本、AIGC 合规 | 不改内容、不改数字、不编模板 |

## 二、总原则（五条铁律）

1. **以产定教**：课程结论必须能倒推到岗位证据。三源（访谈/调研报告/JD）至少两源支撑，否则不下结论。
2. **以岗定课**：课程结构跟随工作领域，不跟随学科目录。
3. **完整工作过程**：每个学习情境走完"资讯→计划→决策→实施→检查→评价"，缺一步就不是情境。
4. **同一结构、不同复杂度**：LF1→LF6 共用六步骨架，复杂度螺旋上升（平行/纵向/包容）。
5. **可测可证**：目标用行为动词，评价用 Rubric 档位，成果用交付物承载。不能留证的目标一律重写。

## 六、交付前自检清单

**通用（8 项）**
- [ ] **已跑本地资产盘点**：A/B/C/D 分级台账在案，未盘点不得说"0 证据"
- [ ] 每条 B 级证据标了源专业与待复核，未冒充一手
- [ ] 每项结论可指回证据来源（访谈/JD/国标/院校数据）
- [ ] **"依据说明"块已写在成果首页**：标准是否获取、替代依据、待校准项、检索日期
- [ ] 术语、模式名、时间线全链一致
- [ ] 版本号已更新，附版本说明与影响面
- [ ] 推断与事实分列，未把推断写成数据

## 七、常见误区（看到就要纠）

| 误区 | 症状 | 纠法 |
|---|---|---|
| 学科化回潮 | 按"第1章绪论、第2章原理"排 | 按工作过程排，章节名改情境名 |
| 任务写成职责 | "负责设备运维" | 任务必须有起点、过程、交付物 |
| 目标不可测 | "熟悉工业协议" | 改"能独立完成 Modbus TCP 与 OPC UA 网关配置并联调通过" |
| 情境变练习 | 只做操作，没有资讯/计划/决策/评价 | 补全六步，重点补决策与评价 |
| 学时打架 | 模块学时之和 ≠ 课程学时 | 建学时台账，改动即四级重算 |
| 人培两张皮 | 方案一套数、进程表另一套数 | 以 Table5 为唯一数据源反向生成 |
| 规格悬空 | 培养规格指不出支撑课程 | 每条规格挂课程与评价，挂不上的删 |
| AI 越界 | 学生用 AI 直接下发配置 | 高危进禁用层，AI 产出人工复核签字 |
| 评价靠印象 | 只有期末一张卷 | 建过程性证据链 + Rubric 档位 |
| 成果=工作罗列 | 通篇"我们做了…" | 用三个问题串，删掉无关工作 |
| 数据无口径 | "就业率 95%"无来源 | 标口径、年份、样本、对比基线 |

## 八、语言与格式

- 默认中文输出，专业术语保留原形（BAG、LF、PGSD-KSA、COMET、Rubric、LOTO）。
- 正式文件给完整 Markdown 结构，编号连续、表格对齐，可直接转 Word/HTML。
- 引用用户既有材料时注明版本号（V70/V80/V2.7 等），改版必须写版本说明与影响面。
