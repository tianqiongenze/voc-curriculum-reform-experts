## 为什么拆团队

六类产出物的评审方完全不同：任务表由企业专家审（真不真）、人培方案由教务与评估专家审（合不合规、闭不闭合）、课标教案由督导审（能不能上课）、成果奖由评审组审（有没有创新、有没有证据）、交件格式由教务处对照上一版找差异（像不像本校的东西）。一个人写六类文件必然失焦；成果奖天然要求"写的人"与"挑刺的人"分离。

七位成员各自覆盖一个完整分析域，域内不跨，跨域由主理人按 SOP 编排。

## 三条主流程

| 流程 | 适用 | 阶段 |
|---|---|---|
| **A 人培方案全流程** | 修订/新编人才培养方案、专业建设整体方案 | 定锚 → 岗位任务 → 能力体系 → 人培编排 → 课标教案 → 审核 → 定稿 |
| **B 课标教案生产线** | 单门课的课标、教案、工单 | 输入确认 → 编制 → 审核 → 定稿 |
| **C 成果奖/论文/课题** | 申报材料、教改论文、课题 | 盘点定位 → 补证据（并行）→ 凝练成稿 → 终审 |
| **D 单点任务** | 只问一件事 | 按路由表直调 1 位成员 |

## 内置方法论

| 支柱 | 用于 |

| PGSD-KSA / COMET / Rubric | 能力矩阵、能力测评、评分量规 |

## 使用示例

- "我要修订工业互联网应用专业的人才培养方案，从岗位调研到六表、课标、教案全流程帮我编排。"
- "按学院格式做一整套课改材料包：六表、人培方案、四门课标加教案，最后直接出 Word 和 PDF 交件。"
- "把这两年的课改成果凝练成教学成果奖申报材料，帮我定成果名称、搭证据链、写创新点。"
- "这门课学时从 92 改成 68，帮我重算学时学分，并列出受影响的表格。"
- "帮我以评审专家视角审一遍这份人培方案，指出必须改的地方。"
- "把 LF1—LF4 全部 11 个学习情境做成两件套：学生互动学习模块（预习＋游戏闯关＋仿真实训＋检测）和教师授课包。"
- "我目录里已经有访谈录和调研报告，先盘点能用什么，再开始干活。"
